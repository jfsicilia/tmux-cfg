# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

Tmux dotfiles managed via GNU Stow. The stow package root is `tmux/`, so stowing from the parent dotfiles directory symlinks `.config/tmux/` into the user's home.

The live config is at `~/.config/tmux/tmux.conf` — edits to either location affect the same file.

## Key Configuration Decisions

- **Prefix**: `Alt+b` (not the default `Ctrl+b`)
- **Terminal**: foot (Wayland), with `tmux-256color` inside tmux and RGB/undercurl overrides for foot
- **Theme**: catppuccin mocha, loaded via `run` (not TPM) — catppuccin options must appear **before** the `run` line
- **Window display**: Uses `#W` (window name) not `#T` (pane title) in catppuccin — `allow-rename off` and `automatic-rename off` prevent the shell from overriding manual window names
- **Pane navigation**: vim-tmux-navigator pattern using `Alt+h/j/k/l` with vim-aware `if-shell` detection — these same keys work in copy-mode-vi
- **Indexing**: Windows and panes start at 1, with `renumber-windows on`
- **Status bar**: Two lines at top (`status 2`). tmux draws `status-format[0]` **above** `status-format[1]`, so to get the session list on top and the bar below, `status-format[0]` is overridden with the session list and `status-format[1]` holds a **verbatim copy of tmux 3.7's default `status-format[0]`** (standard recipe: `status-left` + `#{W:…}` window loop + `status-right`) — re-paste it from `tmux -f /dev/null show-options -gv 'status-format[0]'` if the default ever changes. **Line 1 (lower)** = the bar: left = green session pill `[#S]` (`@catppuccin_status_session` module in `status-left`, set **after** `run` since the module string doesn't exist until then) followed by the window pills; right = a **hand-written** sapphire clock pill in `status-right` (`` cap + clock icon + `%H:%M · %Y-%m-%d` + `` cap, all on `#74c7ec`) — hand-written because the catppuccin module has no per-module separators and the session pill wants a different cap. Session `[#S]` text + its **hardcoded mocha** green/crust colors (`@catppuccin_status_session_text_bg` / `_text_fg`; `#{E:@thm_green}` would resolve empty here, before the theme loads) are set **before** `run`. `@catppuccin_status_connect_separator no` keeps caps/trailing-space on the bar bg, not filled with the pill color. `status-left` has a trailing space to gap the session pill from the first window pill. **Line 0 (top)** = centred plain text, one entry per session via the `#{S/n:inactive,active}` loop, each rendered as `#{@sess_idx}.#{session_name}` — `/n` sorts by session **name** so the list matches the order `switch-client -n/-p` (`prefix )` / `(`) walks; bare `#{S:…}` sorts by session id (creation order), which desyncs from next/prev after a session is killed and recreated. `@sess_idx` is the 1-based position in that name-sorted list, stamped on every session by `scripts/reindex-sessions.sh` (run from the `session-created` / `session-closed` / `after-rename-session` hooks and once at config load) — the format itself has no way to compute a loop index (`loop_iteration` doesn't exist and a nested `#{S:}` shadows the outer `#{session_name}`). Deliberately low-key: **no pills** — only the active session's name is coloured (`@thm_blue` + bold), the rest are `@thm_overlay_1` grey. `list=focus` on the active entry keeps it visible when the list overflows; `range=session|#{session_id}` makes each name a mouse click-target. `@_sess_active` / `_inactive` are pre-baked `#[fg=…]` style strings (`-gF`, no `#{session_name}` inside so early expansion is safe); the format itself is plain `set -g` so `#{S/n:…}` expands per-render. Whole block sits **after** `run` (needs `@thm_*`, `@_ctp_status_bg`)
- **Command prompt**: `message-line 0` — a `:` prompt / message takes over **line 0 (top)**, so the session list is what disappears while typing a command (the bar on line 1 stays). `message-style` / `message-command-style` are re-asserted **after** `run`: `align=left` (catppuccin sets `align=centre`, which offsets the prompt) and `fill=<colour>` — without `fill`, tmux 3.7 only paints the prompt's own width and the session list stays visible behind it

## Plugins

Plugins live in `plugins/` and are loaded directly (no plugin manager like TPM):

- **catppuccin/tmux** — Theme. Configured via `@catppuccin_*` options set before `run catppuccin.tmux`
- **hyoretsu/tmux-persist** — per-session save/restore fork of tmux-resurrect. `@persist-save-on-exit`/`@persist-auto-restore` are **off** (explicit control); `@continuum-restore` is on (boot restore + 15-min save). `@persist-capture-pane-contents` is **off** on purpose: with it on, restored panes replay a `cat` of the saved screen before `exec zsh`, which yields a stray `%` (zsh `PROMPT_EOL_MARK`), duplicated prompts, and — for full-screen TUIs like `claude`/`nvim` — corrupts the `send-keys` that restores the process (replayed terminal query-responses land in the shell's input buffer). Cost: no scrollback in restored panes. Snapshots: `<persist-dir>/<name>_<ts>.tgz` + `<name>_last` symlink. `@persist-dir` is unset → default `~/.local/share/tmux/persist/`.
- **tmux-continuum** — periodic save + boot restore, via tmux-persist's compat wrappers.

## Session lifecycle (sleep / kill / awake / revive)

`scripts/hibernate-lib.sh` + `sleep.sh` `awake.sh` `sleeping.sh` `kill.sh` `killed.sh` `revive.sh` — standalone, not sourced by tmux.conf. **sleep**/**kill** = `save.sh <s>` → move the `<s>_*` snapshot into `persist/sleeping/` or `persist/killed/` → `kill-session`. **awake**/**revive** = move it back → `restore.sh <s>` → `switch-client`. The subdirs are the whole trick: `restore.sh all`, continuum's boot restore and the age-based pruning all glob `<persist-dir>/*_last` at the **top level only**, so a parked session never auto-revives and never expires. `sleeping.sh`/`killed.sh` print the parked names (for the fzf pickers).

**workmux sidebar — two separate problems:**

1. *Double sidebar on new sessions* (a workmux bug, not ours). `workmux sidebar on` installs `after-new-session[99]` + `after-new-window[99]` hooks that each run `workmux _sidebar-sync`; on a `new-session` both fire for the first window and, being `run-shell -b`, race — each splits in a `@workmux_role = sidebar` pane. Hits **every** plain-`new-session` path (`sesh connect`, `workmux add`, `tmux new`, `sessmgr n`). Fix: `scripts/wm-sidebar-dedup.sh` on `after-split-window[50]` (workmux builds the sidebar with a split) reaps all-but-the-first sidebar pane in the window — a sidebar pane is `@workmux_role = sidebar` **or** `pane_start_command` matching `_sidebar-run` (the tag lands a beat after the split; the start-command match closes that gap). Fixed index so a reload replaces it not stacks; lives in a slot workmux never touches, so it survives `workmux sidebar off`/`on`, `workmux setup` and upgrades. No-op for ordinary splits. This is the robust self-contained fix — every "prevent it" alternative has to own workmux's `[99]` hook slots, which `workmux sidebar on` reinstalls. **The `sessmgr n` binding is a plain `new-session`** — no wrapper script.

2. *Sidebar injected mid-restore* (scrambles pane cwds because `select-layout` gets a pane-count mismatch). Only `awake`/`revive` hit this. `hib_stash` kills existing sidebar panes **before** `save.sh` (snapshot stays sidebar-free); `hib_unstash` suspends workmux's `after-new-*` hook slots (index-preserving, `_hib_wm_hooks_suspend`/`_restore`) for the duration of `restore.sh`, then runs one `_sidebar-sync` per window. An already-scrambled live session must be recreated before its first clean sleep/awake.

After `restore.sh`, `awake`/`revive` run `hib_reassert_processes`: tmux-persist restores a pane's program by `send-keys`, racy against a slow interactive zsh still sourcing its rc (keystrokes dropped → bare prompt); the net waits `HIB_REASSERT_DELAY` (2s) then re-sends any allow-listed program missing from an otherwise-idle pane. It matches the Nth **non-sidebar** pane of a window to the Nth saved pane (saved indices can't be trusted once workmux re-adds the sidebar as pane 1). Bound under `prefix + S` → `sessmgr` key-table (`n` new session — `command-prompt` for the name; `z`/`Z` sleep / awake-picker, `k`/`K` kill / revive-picker — `z` and `k` behind a `confirm-before … (y/n)`; `s`/`S` save all/current, `w`/`W` save+detach all/current, `t` sesh-last, `d` detach); kanata's `sessions` layer sends `prefix S <key>`.

## workmux worktrees (`prefix + W` → `workmux` key-table)

`n` add (prompts branch) · `r` rename (prompts) · `m` merge · `k` remove · `b` rebase · `w` close · `d` dashboard picker. Each opens a `display-popup` at `#{pane_current_path}` running the `workmux` subcommand; `m`/`k`/`b` gate on `confirm-before … (y/n)`. No helper scripts — all inline in the binds. Ported from the old kanata `worktree` macros (which drove it by typing into the command prompt).

- Every command is prefixed **`TMUX_PANE=$(tmux display-message -p '#{pane_id}')`** — a popup's shell doesn't inherit `TMUX_PANE`, and without it `workmux` errors ("Cannot determine the tmux session …") whenever more than one session is open. `display-popup` does NOT format-expand `-E`, so the `$(…)` runs in the popup shell, where `#{pane_id}` resolves to the client's active pane. (In the `command-prompt` templates for `n`/`r` the `$` is written `\$` so tmux's own `$`-expansion leaves it alone.)
- `n`/`r` use `command-prompt`'s **string** form, not a `{ }` block — `%%` substitution does **not** happen inside `{ }`.
- No per-worktree `1`-`9` jump: `workmux open`/`list` are per-repo, and tmux can't feed a digit into a popup, so the old kanata "open dashboard + press N" doesn't port. Use `d` — the dashboard's own 1-9 quick-jump works, and across projects.

## workmux agents (`prefix + A` → `agent` key-table)

`Space` dashboard (agents tab) · `l`/`h` next/prev agent (sidebar order) · `1`-`9` `workmux sidebar jump <N>` · `d` `workmux last-done` (jump to the agent that just finished / is waiting) · `a` `workmux last-agent` (toggle last two). Ported from the kanata `agents` macros. The jump/next/prev/last-* commands are plain `run-shell -b "TMUX_PANE=#{pane_id} workmux …"` (no popup — they just switch the client); `run-shell` format-expands `#{pane_id}`. `Space` is a `display-popup` with the same `$(…)` TMUX_PANE prefix as the worktree binds. Unlike worktrees, `sidebar jump N` **is** a real cross-session primitive, so `1`-`9` port directly.

## When Editing

- Catppuccin `@catppuccin_*` options must be set **before** `run ~/.config/tmux/plugins/catppuccin/tmux/catppuccin.tmux`
- The vim-tmux-navigator block (lines ~52-68) has version-conditional bindings for `C-\` — preserve both the `< 3.0` and `>= 3.0` branches
- `scripts/` stows to `~/.config/tmux/scripts/`. `reindex-sessions.sh` keeps `@sess_idx` (the session number in status-format[0]) in sync — keep its sort (`LC_ALL=C sort`) matching the `#{S/n:…}` order the status list renders, and it ends with `refresh-client -S` (setting an option doesn't repaint the bar). Its hooks are **separate entries** from the `sesh cache refresh` hooks (via `set-hook -ga`), never `;`-chained after them — `sesh cache refresh` takes ~10s here and would delay the reindex. `tmux-layout.sh` is a standalone helper (not sourced by tmux.conf): builds a pane layout from a `[2|1[2/3]]`-style spec (`|` columns, `/` rows, integer weights) and runs positional commands in the leaf panes — see its `-h`. `hibernate-lib.sh` + the sleep/kill/awake/revive/sleeping/killed scripts — see "Session lifecycle" above; the filename `<->` session-name encoding in `hibernate-lib.sh` (`_hib_enc`/`_hib_dec`) must stay in sync with tmux-persist's `helpers.sh` (`%` then `/`).
- Reload config with: `tmux source-file ~/.config/tmux/tmux.conf`
